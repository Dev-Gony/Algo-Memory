# 통근 Python 실행 채점

공식 [Pyodide 0.29.4](https://pyodide.org/en/0.29.4/usage/index.html)를 브라우저 Worker에서 실행합니다. 답안 문자열과 비교하지 않고 `solution`에 정상·경계 입력을 넣어 반환값을 검사합니다. 다른 변수명·컴프리헨션·표준 라이브러리 풀이도 인정하며, 입력 불변 조건이 있는 문제는 리스트 변경도 검사합니다. 제공된 테스트 통과가 모든 가능한 입력의 정답을 보장하지는 않습니다.

## 격리와 오류

앱은 고정 CDN 파일 5개를 자격증명 없이 받고 크기와 SHA-256을 검증한 뒤 바이트만 sandbox iframe으로 전달합니다. iframe에는 `allow-scripts`만 있고 `allow-same-origin`은 없습니다. 그 안의 Blob Worker에서 Python을 실행합니다. CSP의 `connect-src 'none'`과 `default-src 'none'`으로 네트워크를 차단하고, 런타임 파일 요청은 검증된 메모리 자산으로만 제공합니다. 추가 스크립트·패키지를 내려받지 않습니다. `js` 모듈에는 빈 전역 객체를 제공하고 DOM·부모 문서·계정·앱 저장소를 전달하지 않습니다. Worker의 IndexedDB는 불투명 출처에서 접근할 수 없습니다.

매 실행마다 새 iframe·Worker·인터프리터를 만들고 결과·중단·오류 후 폐기합니다. 다운로드 45초, 초기화 30초, 답안 실행 3초를 나눠 제한합니다. 무한 반복은 부모 페이지가 iframe을 제거해 종료하며 다음 시도는 새 Worker에서 시작합니다. 사용자 답안을 호스트나 서버의 Python으로 실행하지 않습니다. 브라우저 자원은 사용하므로 OS 수준의 메모리 할당량이나 외부 저지의 부정행위 방지 기능까지 제공하는 것은 아닙니다.

실행 통과·테스트 오답·문법 오류·실행 오류·시간 초과·로딩 실패·네트워크 실패·중단을 구분합니다. 다운로드·초기화·연결 실패와 중단은 학습 오답으로 기록하지 않습니다. 실행 없이 자가 확인도 가능하며 미검증으로 표시합니다.

## 로딩과 오프라인

최초 런타임 파일은 **12,286,632바이트, 약 12.3MB(압축 전 합계)**입니다. 실제 전송량은 CDN 압축에 따라 달라집니다. 모바일 속도에 따라 처음 준비에 시간이 걸리며 상태와 중단 버튼을 표시합니다. 답안은 외부 서버로 전송하지 않습니다.

검증한 파일을 Cache API에 보관하고 읽을 때도 해시를 검사합니다. 열린 페이지에서는 메모리 자산도 재사용합니다. 캐시가 완성된 후 런타임 네트워크를 차단한 실행을 검증했습니다. 캐시 삭제·시크릿 모드·`file://`에서는 영구 보관을 보장하지 않으며 재다운로드가 필요할 수 있습니다. 캐시가 없는 오프라인에서는 Python 실행이 불가능합니다. 앱의 오프라인 재방문을 위한 서비스 워커/PWA는 없습니다. 이미 열린 화면이나 받은 HTML의 편집·자가 확인은 별개입니다. 기존 글꼴·선택적 PC 계정 기능의 네트워크 의존성은 유지합니다.

## 저장 호환

기존 PC `algo-memory:v1`와 계정 동기화는 유지합니다. 새 통근 데이터는 `algo-memory:commute:v2`에 저장합니다. 기존 통근 v1 키는 덮어쓰지 않고 복사하며 시도·초안·복습 날짜를 보존합니다. 예전 `self-pass`는 `verified: false`이고, 과거 단계는 `legacyStage`에 남깁니다. 새 실행 검증 단계와 연속 실행 통과는 0에서 시작합니다. 예전 자가 확인을 실행 정답으로 승격하지 않습니다. 손상·미지원 형식은 덮어쓰지 않고 경고하며 v1/v2 백업을 복원할 수 있습니다.

실제 결과는 `method: python-tests`, `engine: pyodide-0.29.4`로 기록하며 실행 통과만 `verified: true`입니다. 힌트·풀이 열람과 독립 통과를 구분합니다. 독립 실행 통과는 1·3·7·14·30일, 도움 후 통과나 실패는 다음 날 복습합니다. 3분 이내 독립 실행 통과 2회면 한 단계 올리고 실행 실패는 한 단계 낮춥니다. 자가 확인으로 실행 단계나 난이도를 올리지 않습니다. 새로고침한 결과는 중복 기록하지 않습니다.

## 검증 재현

`npm test`, `npm run lint`, `npm run test:commute-catalog`, `npm run test:browser`, `npm run test:python-browser`를 사용합니다. 브라우저 검사는 설치된 Chrome/Edge를 사용하며 `BROWSER_PATH`로 지정할 수 있습니다. `node test/cache-python-runtime.js`로 공개 런타임을 검증해 미리 받고 `PYODIDE_TEST_DIR`을 그 경로로 지정하면 브라우저는 같은 바이트를 테스트 사본으로 받습니다. 코드 실행은 실제 브라우저 WASM에서 수행합니다. `PUBLIC_QA_URL`은 기존 배포 사이트를 새 테스트 브라우저 데이터로 검증하는 옵션입니다. 계정 제공자는 기존 롤백 플래그와 SDK 차단으로 사용하지 않습니다.

실제 런타임에서 10개 모범 풀이·다른 풀이·오답, 문법/실행 오류, 입력 변경, 무한 반복과 취소 뒤 복구, Worker 간 상태 격리, fetch/XHR/WebSocket 차단, 부모 문서·저장소 접근 거부, 오프라인 캐시와 연결·로딩 실패를 확인합니다. 모바일 UI는 375/412/915px·터치·입력 도구·실행·오답·시간 초과 후 재시도·힌트·기록 복원을 검사합니다. 서버는 127.0.0.1에만 바인딩하며 테스트 후 닫습니다.

실물 S23 Ultra의 Samsung Keyboard/Gboard와 iOS 키보드는 미검증입니다. IME와 키보드 공간 변경은 자동 시뮬레이션 범위입니다.
